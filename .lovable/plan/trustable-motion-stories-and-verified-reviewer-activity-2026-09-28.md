# Trustable motion stories and verified reviewer activity

## What will be built

### 1. Cinematic Trustable motion stories
- Create a reusable responsive SVG motion system using Trustable’s existing graph, gate, vault, and Live/Reference visual language.
- Add three polished sequences: **Intent to immutable receipt**, **Denied request at the security gate**, and **Trustable organism growth**.
- Animate packets, node activation, gate decisions, latency, and ledger receipts; provide replay, pause, scene selection, and reduced-motion behavior.
- Place the strongest sequence on the public homepage and reuse the same renderer in Architecture without turning either page into a video mockup.
- Keep every statement evidence-based: current Trustable actions are **Live**; OASA, VAULTABLE, and unconnected enterprise systems remain **Reference architecture**.

### 2. Tooling and module alignment
- Follow the CoachCompass direction already documented for a reusable `FlowDiagram`: SVG, semantic design tokens, responsive layouts, and reduced-motion support.
- Use a lightweight React motion library only for sequencing and path progress; retain SVG/CSS for rendering and avoid a heavy 3D stack.
- Reuse Trustable’s `GraphWorkbench`, `HeartVault`, `ProofBadge`, tooltip, and report-action patterns.
- Record that no callable EngineWare global motion/content-catalog module was found. Do not present a module or backend integration as connected until its contract is available.

### 3. Honest admin activity view
- Upgrade the Audit workspace with an **Activity coverage** summary separating four signals: identity-provider sign-ins, tenant membership, immutable business events, and anonymous aggregate traffic.
- Show named reviewer status only from verified records, including Luke’s sign-in-without-role state and explicit “no record” states for Kevin, Jessica, and Matt.
- Explain in the interface that aggregate visitors/pageviews are anonymous and that historical clicks cannot be reconstructed.
- Preserve the existing tamper-evident ledger as the source of truth for privileged actions; never imply analytics are immutable ledger entries.

### 4. Future named interaction capture
- Define a privacy-minimal, allowlisted event contract for authenticated page views and meaningful commands only—no keystrokes, form contents, secrets, or blanket DOM click capture.
- Keep this portion blocked and visibly labeled until the protected backend owner supplies or approves a write contract through the enterprise execution boundary.
- Do not modify protected backend, contract, database, or EngineWare files.

## Verification
- Run type checks and focused tests for sequence state, reduced motion, and activity-status classification.
- Browser-test desktop and phone layouts in light and dark themes; verify replay/pause, keyboard operation, tooltips, overflow, and zero console errors.
- Verify every displayed person, count, timestamp, Live badge, and Reference badge against its actual source before publishing.
