# Trustable Flow Pilot Experience

## Goal
Turn Trustable Flow into the real mobile-first experience Bob receives during a two-week enterprise pilot: simple enough to create a useful flow immediately, powerful enough for IT, security, engineering, and audit teams to inspect every detail.

## Experience
- Replace the plain two-panel gate form with a guided mobile creation journey using clear language: describe the work, review mapped systems and sensitive data, confirm safety gates, launch, and see measurable impact.
- Show continuous positive progress and concrete KPIs so Bob feels confident and proud of the flow he created, without manipulative or addictive interaction patterns.
- Keep advanced controls available through drill-downs rather than crowding the default experience.

## Flow catalog
- Add a searchable, faceted catalog with dozens of realistic templates across roles, departments, functions, categories, risk buckets, and workflow types.
- Clearly identify templates with role icons, connector icons, status badges, risk tags, creation time, last-used time, ownership, and measured impact.
- Support preview, select, edit, save, save as, update, share, and global report actions.
- As Bob types, show matching templates, recommended next steps, mapped company services, data classifications, and likely connectors.

## Live flow map
- Add a responsive animated node map showing triggers, systems, data, Trustable gates, approvals, actions, latency, warnings, and successful checks.
- Every node and edge opens details, copy/actions, and sanitized request information.
- Surface contextual actions such as “Send to Red Team” when a gate or data path needs adversarial review.

## API and expert mode
- Add an API/code toggle that shows the sanitized, parameterized live request with copy and open-console actions.
- Add a full-width API Console for searchable calls, detailed telemetry, filters, multi-select, saved queries, generated endpoint documentation, and live OAS/sub-spec exports.
- Clearly label the current Lovable Cloud implementation as Live and the future EngineWare/MyCDB SQL Server source-of-truth connection as Reference architecture until the direct connection contract exists.

## Landing explanation
- Explain the creation loop in plain language: describe work, Trustable maps it, safety checks run, Bob approves, value is measured, and successful flows combine into larger solution packages.
- Emphasize measurable ownership, confidence, and enterprise safety without overstating unavailable integrations.

## Global interaction rule
- Every multiple-choice experience marks a recommended choice and always includes an Other option with free-text entry.
- Retain AI assist, library insertion, tooltips, drill-downs, shadows, and global export/share/analyze actions.

## Technical notes
- Keep existing protected authorization and execution files unchanged.
- Build the new catalog and experience in presentation code first; persist new flow definitions only after an approved backend contract is available.
- Do not claim SQL Server, EngineWare, MyCDB, Outlook, or any connector is live until it is connected and verified.
